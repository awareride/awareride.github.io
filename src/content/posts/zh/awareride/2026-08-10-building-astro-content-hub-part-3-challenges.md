第一篇是"为什么"，第二篇是"怎么做"。这是我最喜欢的部分：那些不顺利、或者比预期更奇怪的细节。

## 子路径部署的陷阱

早期我就希望 hub 不仅能部署在域名根，也能部署在子路径下（比如 `org.github.io/hub/`）。听起来小事一桩，其实不然。

两个 bug 咬了我：

- **子路径下语言检测失效。** 用来判断当前语言的代码假设路径第一段就是语言，但当 base 路径挡在前面时这是错的。修复方式是让路由解析把 `base` 考虑进去。
- **canonical URL 指向了错误的位置。** 我必须在 `site` 配置里把 `base` 恢复回来，这样 canonical 链接、sitemap、RSS 才能尊重部署前缀。

教训：*任何读取 `Astro.url` 或切分路径的代码，从第一天起就必须知道 `base` 的存在。*子路径部署是一等需求，不是事后补丁。

## 三轮移动端搜索拉锯战

搜索功能（Pagefind + 自定义弹窗）在桌面上完美。在真机上却成了一系列笑中带泪的 bug，每一轮都暴露更深一层：

1. **空白的下拉面板。** 带子项的导航下拉（Products、Community）显示为空，直到你点一下才出现。根因：移动端弹窗上的 `align-items: stretch` 让面板在没有结果时也纵向撑开——桌面端保持 `flex-start`，所以桌面从不出现。
2. **结果被键盘遮住。** 真机上，屏幕键盘会缩小*视觉*视口，但 `position: fixed` + `vh` 单位量的是*布局*视口。于是结果列表延伸到了键盘后面。桌面模拟器没有真实键盘，所以 DevTools 里从不复现。
3. **Android 底部手势条。** 即便修了键盘问题，结果仍溢出安全区——Chrome 在全屏 Android 手机上保留了一条底部手势条。修复方式是对弹窗容器使用 `env(safe-area-inset-bottom)`，并把尺寸按视觉视口来定。

结论：**桌面设备模拟器会在移动端问题上骗你。** 只要涉及键盘、安全区或 `vh`，就必须在真机上测。

## "模板税"与升级难题

最深的设计问题其实不是技术性的——而是：*使用者怎么升级这套模板，才能免去痛苦的迁移？*

不存在零迁移的升级。一旦使用者改了品牌，他就分叉了。目标是把"必然冲突"的surface缩到极小，并集中到少数几个可预测的文件里。这就是为什么 `ARCHITECTURE.md` 把仓库分成三层：

- **Machinery** 应该进化（修 bug、加功能），使用者不该碰它。
- **Your site** 必然分叉（品牌、产品、样式），但新功能有时会动到它的接口。
- **Extensions** 是可选的钩子，按需复制，而不是必须跟着升级。

我甚至在发布前**用一个临时 git 仓库实测验证了升级路径**：重命名一个 Machinery 文件（`index.astro` → `home.astro`）能干净合并，却悄悄丢失了上游路径——git 检测不到。于是我做了 `check:upstream`，一个专门捕捉这类"静默断裂"的漂移守卫，并写了一篇升级指南。

教训：*模板真正的产品是它的升级故事，而不是首次运行的体验。*

## 最小化的交互式 Markdown —— 学会放手

我想要交互式文档：一个点了会有变化的按钮、一个用 JS 函数渲染 SVG 图表的例子。我第一反应是发布一套内置组件库（`Counter`、`InteractiveChart`、`Tabs`、`Callout`）。

随后一个更尖锐的问题来了：*外部仓库拥有它们自己的交互性。只有内容持有者才知道自己需要什么交互。* 发布一套固定的组件库，既限制了他们，又让模板背负了大多数使用者用不上的代码。

于是我**翻转了决定**：让 MDX 支持保持最小（注册 `.mdx`，让作者 import *自己的*组件），并丢掉内置的组件库。模板保持精简，外部仓库保持独立、互不干扰。这个取舍在 authoring 指南里被公开写明了。

教训：*当某项能力的真正 owner 是"别人"时，别自己造——让它变得可能就好。*

## 一个意外收获：放错目录的文档

在构建交互式 Markdown 示例时，我把一个 `.mdx` 文件放到了 `src/content/docs/astro-content-hub/en/`，但这个产品的 `base: './docs'` 意味着它的文档其实在仓库根的 `docs/`。文件就是没出现。调试这个"消失的页面"反而让我看清了真实的内容解析规则，并收紧了 `doc-dirs` 机制。一个 bug，比读代码更让我懂了这个系统。

## 我想对过去的自己说的话

- 把 `base` / 子路径当成第一天就要满足的约束。
- 任何移动端的东西都在真机上测，别信 DevTools。
- 在功能之前先设计升级路径，而不是之后。
- 优先"让它变得可能"，而不是"替他们造好"。

这就是完整的故事——为什么、怎么做、以及那些粗糙的边缘。项目采用 MIT 协议，可免费运行在 GitHub Pages 和 Cloudflare Pages 上，并且就是为了被 fork 和升级而存在的。
